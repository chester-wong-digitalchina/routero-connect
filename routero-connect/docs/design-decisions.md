# Design decisions

These decisions describe the current implementation, not a promise of general model or platform support. The [handoff](handoff.md) tracks remaining acceptance work.

| Decision | Reason | Consequence and implementation |
| --- | --- | --- |
| Configure the native client rather than proxy its traffic | Preserve native tools, approvals and sandbox behavior; keep this plugin's scope small | `src/adapters/codex/` writes provider settings. Codex talks to Routero directly; the plugin cannot repair gateway request translation at runtime. |
| Share one CLI/configuration engine between terminal and GUI | Avoid inconsistent writers, validation rules and recovery behavior | `src/ui/controller.ts` orchestrates `src/ui/cli-runner.ts`; `src/cli/codex.ts` delegates to `src/adapters/codex/adapter.ts` and `src/config/`. |
| Use Windows Credential Manager with a separate command-backed helper | Avoid plaintext keys in Codex configuration and avoid assuming Codex can read VS Code SecretStorage | `src/credentials/` enforces origin/reference ownership. Keys travel through memory/stdin, not arguments. The helper remains usable independently of extension updates/uninstall. |
| Pin helper runtime/path/hash and stage new directories | Avoid silently replacing a live authentication dependency | `stage-helper.ts` and `adapters/codex/runtime.ts` inspect private manifests/scripts. Hashes detect changes; they do not defend against a malicious process with the same Windows identity. |
| Separate model visibility from compatibility approval | A successful list or simple text reply does not demonstrate tool continuation or safe model limits | `src/core/compatibility.ts` and `compatibility/models.json` preserve unknowns and failed observations. Current key visibility must be refreshed; caller-provided approval is not trusted. |
| Add a narrow isolated validation gate | The Luna calculator task passed, but exact limits are unavailable; blocking all experimentation would prevent checking plugin-generated parity | `src/core/coding-validation.ts` permits only explicit UAT/Luna/Codex 0.172.0 validation in the dedicated home. Normal eligibility is unchanged; there is no generic force flag. |
| Preview, revision checks and three-way recovery | Preserve unrelated settings, comments and later edits; avoid blind whole-file restoration | `src/config/` writes private recovery before atomic replacement, seals plans, checks revisions and reports rollback conflicts. Recovery stays outside Git and does not depend on the gateway/helper. |
| Resolve the executable's stable installation link only for read-only detection | Official Windows Codex installations use a linked `bin` directory | `resolveCodexExecutable` verifies the canonical release, probes `--version` with bounds and rechecks selection. Apply rejects a changed release after preview; configuration/recovery write-link protections remain strict. |
| Clean the managed child environment without altering the host | VS Code may carry personal authentication or Electron/Node overrides unrelated to the selected Routero setup | `src/ui/cli-runner.ts` uses an allowlist and names-only diagnostics. Direct standalone CLI execution retains environment-conflict checks. |
| Exclude printable unsupported model aliases with a warning | Two aliases previously invalidated an otherwise useful 16-entry gateway list | `src/adapters/codex/gateway.ts` retains valid IDs, reports an exclusion count and still rejects malformed, secret-bearing or duplicate valid IDs. No alias is guessed or translated. |
| Keep model tests explicit and bounded | Avoid unexpected charges and misleading compatibility claims | The fixed text probe requires credit consent, uses no tools and does not promote model support. Native coding acceptance is separately authorized; a token bound is not a dollar cap. |
| Preserve evidence provenance and historical checkpoints | Source inspection, screenshots, synthetic tests, installed-host smoke and real coding tasks establish different facts | Historical reports retain their scope; current status is summarized in `handoff.md`. Shared-controller automation is not described as a completed GUI click-through. |

We deferred automatic dependency installation, persistent profile management, model approval without authoritative metadata, the Codex IDE adapter and other clients/platforms. These expand responsibility or require independent evidence. A passing small CLI task does not remove those requirements.
